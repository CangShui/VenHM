## 三层结构：哪层是「翻译」，哪层是「自建」

| 层 | 上游 | 本工程 | 风险 |
|---|---|---|---|
| 模型 / 存储 / 源契约 / UI 数据流 | ✅ 有 | 部分对照移植，仍存在语义偏差；不得笼统称逐文件完整翻译 | 中，需逐功能验证 |
| ArkTS ↔ QuickJS 桥 | ❌ 上游是 Dart FFI 直连、零序列化 | **自建**（`value_bridge.h` + `napi_init.cpp`） | 中，已用自检矩阵覆盖 |
| HTML/CSS 解析引擎 | ❌ 上游用成熟库 `package:html` | **自建**（`html_engine.js`，约 790 行） | **高，仅有少量离线用例，远未覆盖全源** |

第三条是本工程最大的技术债：我手写了一个 HTML 解析器 + CSS 选择器引擎去替代一个成熟库。
`tools/html_engine_cases.js` 只覆盖了 manhuagui 用到的选择器链路，**远不足以说明它等价于 `package:html`**。
凡是"选择器莫名选不中 / 属性读不到"的源级失败，先怀疑这一层。

   这一级能区分「移植坏了」和「这个关键字本来就没结果」——
