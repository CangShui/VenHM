## 撤回此前对源问题的过强判断

### 绅士漫画：确实存在应用请求适配差异，不能怪源

此前仅根据移动模板的旧选择器零命中就说“站点改版、源过期、不是迁移问题”，证据不足，现撤回。

1. [固定提交原版网络实现](<../logs/upstream/app_dio-7110c19.dart#L283-L285>)默认 `User-Agent: VeneraNext/v1.17.0`。
2. 移植网络层给未声明UA的源调用注入手机浏览器UA，使手机收到 `/themes/mo/` 移动页面。
3. 对之前移动页面做**同导出响应文本**对照：30个安装源selector+16个移动selector×3响应×2运行时，共276次，独立lxml、生产HTML引擎和真实主机NAPI完全一致。说明不是selector引擎丢元素，**但不排除应用选错模板**。
4. 恢复源请求的固定原版UA，保留源显式UA优先级，未修改安装源脚本；WebView/浏览器UA不作全局替换。
5. 同手机、同公开搜索URL、无Cookie：[新响应证明](<../tools/wnacg_html_reference/phone-upstream-ua/phone-1.proof.json>)记录HTTP200、`text/html; charset=UTF-8`与UA；独立parser得到`p.result > b`=2、桌面漫画列表=24。
6. 真正经源适配器/UI搜索得到24条，点“加载更多”增加到48条；进入详情/单章，正文得到121页，侧边单击1→2。不是只看到原始HTML就宣布源可用。

仍有明确失败：WNACG探索首页返回空。当前首页HTML与该源旧home规则仍有不匹配，应独立修复或明确提示，**不能把搜索恢复说成全源完整可用**。
原始响应是UTF-8导出的SDK解码文本，不是原始wire实体字节；不夸大wire编码验证。

### Komiic：旧验证器要求不存在的第二页

[安装脚本](<../logs/user8-installed-scripts/Komiic.js#L252-L299>)搜索只发keyword，明确返回`maxPage:1`。
因此两页相同是源声明的有限单次结果，不是分页迁移失败。新验证器尊重有限maxPage/cursor结束，不再造第二页；保留旧JSONL原始记录，不倒改历史为PASS。

### Shonen与HTTP错误：只记观察，不用关键词定责

`SyntaxError '<'`本身不能证明403；主机不同网络403也不能证明旧手机那次403。
另一次[手机启动日志](<../logs/user8-newbuild-startup-20261014.log#L1057-L1066>)在同Trace上记录403后才JSON失败，适用范围仅那次。
SDK `code401 Parameter error`不是HTTP401。源码的未检状态JSON.parse是错误掩盖机制，不直接证明网络/WAF具体根因。

## 修掉的验证器缺陷

- 分类原先一个target异常会跳过同源后续item/part；现在每目标独立try/catch，输出part/item/phase。
- 原“无公开失败”判定漏掉category，nhentai/ykmh分类失败仍被称通过；现在纳入category。
- 搜索尊重`maxPage:1`与无next结束，不把一次性搜索判分页错误。
- TypeError/JSON异常不凭正则自动归A/C；HTTP响应、SDK错误码、登录要求只作观测分类，不免除迁移适配排查。
- 新错误UI只显示固定技术类型/HTTP或SDK码、设置缺失/登录提示与trace，不回显任意HTML、token、账号或响应正文。
