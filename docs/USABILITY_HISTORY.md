# 阅读历史与续读：可用性验收记录

## 结论与验收口径

本轮完成了**历史列表、准确的源定位、进程重启续读及本地阅读链路的部分验收**，不是全应用可用性通过。

用户目标：除确证的源规则自身问题外，其余场景应与原版一致并能通过可用性检测。执行时分为三层：

1. **应用层**：本地确定性样本、持久化、导航、UI、异常、取消/重试。失败属于 HM，不归因于源。
2. **源兼容层**：同一规则的解析/桥接/加密/网络协议与原版对照。HM 独有失败不算规则豁免。
3. **站点/规则层**：只有上游代码或原版对照的可复现证据才能豁免；HTTP 401/403、未配置账号、VPN 不稳不能直接标为源代码坏了。

## 本轮实现

- 历史表原地增列 `source_key`、`ep_id`，不删表、不清空旧数据。NULL 章节 ID 表示旧序号记录，空字符串是有效的单章节 ID。
- 保存使用一条同步原子 UPSERT：快速翻页不会因分离 SELECT/REPLACE 丢时长和旧页覆盖；不再覆盖已读章节列。
- 首页不再猜测“第一个源”。旧记录只在 hash 唯一匹配时打开，缺源或 key/hash 不一致报错并保留数据。
- 历史页提供100条分页、懒加载封面、详情、续读、单条/批量/全部确认删除、多选/全选/反选。
- 阅读器支持稳定 ID、旧1-based序号和页码恢复；失败详情、失效章节、空图片不伪造成功进度；快速切章锁；退出后忽略旧响应。
- 详情主按钮续读，手动章节从第一页开始；保存真实元数据。未翻页退出也累计阅读时长，重复退出回调不重复累计。
- 新增 **历史 → 离线验收**：手动运行隔离 SQL 测试、生成2章×3页的本地测试漫画、检查持久进度、定向清理样本。

```powershell
# Node >=22.13；本轮使用DSH bundled Node 24
node tools/history_reader_cases.js

# 构建使用现有 DevEco 工具链；见 HANDOVER.md
# 设备：Venera HM 顶栏「历史」→「离线验收」
# 1. 运行历史逻辑回归，应出现4组PASS。
# 2. 打开本地样本详情 → Chapter_2 → 翻到第2页 → 返回。
# 3. 强制重启，从历史首条继续阅读，应恢复2章2页。
# 4. 切到瀑布流后重复重启，检查图片内容/页码/未裁切。
# 5. 恢复原阅读模式，离线验收中清理样本，不清空用户历史。
```
